# Архитектурные решения

## ADR-013 — украинский пилот публикуется только как test-only review StylePack

**Статус:** принято 2026-10-13.

**Контекст:** открытые single-line fonts не дают проверенного украинского
school-cursive набора с направлением пера, anchors и provenance. Контурные OFL
fonts не содержат центральной траектории. Автоматическое восстановление
skeleton из них создало бы неподтверждённый порядок штрихов.

**Решение:** подготовить вручную authored central-line набор
`ua-school-v1-pilot/0.1.0`, использовать существующий StylePack runtime и
сохранить `test_only=true`, `production_eligible=false`. Имя продуктового
`ua-school-v1` не присваивать. Отдельно хранить provenance, frozen word/pair
corpus и визуальные artifacts. Технический `approved=true` означает, что
immutable snapshot прошёл schema/hash/geometry gate; он не означает V-01/V-02.

**Следствие:** можно проверять настоящие joins, marks и весь виртуальный
конвейер без ложного заявления о готовом почерке. Выпуск остаётся заблокирован
художественной правкой, полным покрытием, тремя вариантами и человеческой
приёмкой.

Версия 1.0 · 2026-10-12. Доказательства о внешних проектах: [RESEARCH.md](RESEARCH.md). Численные настройки и форматы: [DATA_MODELS.md](DATA_MODELS.md).

## ADR-01. Собственное ядро с узкими адаптерами — принято

| Критерий | A: всё самостоятельно | B: форк генератора | C: своё ядро + компоненты |
|---|---|---|---|
| Трудоёмкость | Высокая, включая парсеры и CV | Низкая для демонстрации, высокая для UA и разделения подсистем | Средняя, ограниченная предметными задачами |
| Риск | Ошибки в повторной реализации стандартных средств | Наследование ограниченного алфавита, порядка штрихов, лицензий | Риск адаптеров и собственного почерка явно изолирован |
| Скорость к MVP | Медленная | Быстрая демонстрация EN, не доказанный UA MVP | Быстрый каркас; данные определяют критический путь |
| Поддержка | Всё поддерживает команда | Большие слияния с upstream либо отрыв форка | Замена внешнего компонента через контракт |
| Качество письма | Зависит от данных | Не переносится автоматически между языками | Проверяется отдельно от качества библиотек |
| Лицензии | Проще код, данные всё равно проверяются | AGPL/отсутствие лицензии у части кандидатов | Разрешительные библиотеки; свой набор данных |
| Производительность | Потенциально хорошая, нужна работа | Неопределённа на целевом тексте | Локальное CPU-ядро, пакетная геометрия, кэш слов |
| Расширение | Можно, но дорогой старт | Часто привязано к архитектуре форка | Единый IR и отдельные источники стилей |
| Передача Codex | Слишком много новых решений | Легко скопировать чужие ошибки | Явные контракты, инварианты и пакеты задач |

Таблица — инженерная оценка, не измеренный бенчмарк. C принят. Повторно оценить B только если появится лицензированный, поддерживаемый движок с проверенной UA скорописью и сохраняемым порядком штрихов.

## ADR-02. Python и локальный модульный монолит — принято

Python 3.12, библиотека и CLI. Два обязательных внешних runtime-пакета: Pydantic и regex. Геометрия ограничена линиями/квадратичными/кубическими кривыми. Отдельный процесс нужен позднее только для конфликтующих тяжёлых ML-окружений. Не создавать HTTP-сервисы, брокеры сообщений и базу сервера для MVP.

## ADR-03. Canonical Stroke IR — принято

Наши типы владеют порядком, направлением, происхождением и единицами. Классы внешних библиотек не пересекают публичные границы. Поддерживаются геометрический Stroke и операционный PenPlan; это связанные, но разные уровни. SVG — экспортная проекция, не исходная база.

## ADR-04. Unicode и отсутствие молчаливых подмен — принято

NFC, расширенные графемные кластеры, source map. Не применять NFKC, casefold и латинско-кириллическую подмену. Поддержка конкретной графемы доказывается manifest стиля. Неизвестные графемы блокируют окончательный экспорт всей работы. Диагностический режим может показать пропуск рамкой, но такой документ не превращается в машинное задание.

## ADR-05. Стартовый стиль — собственные данные

Собрать `ua-school-v1`: общий набор UA/RU/EN, направленные пути и утверждённые соединения. Основной способ — авторская отрисовка центральных линий в готовом SVG-редакторе с ручным заданием порядка; ещё лучше — реальные записи пера готовым инструментом. Исходники и лицензия данных отдельны от лицензии программы. Не использовать чужой неизвестно лицензированный sample font как дефолт.

## ADR-06. Управляемая скоропись

Лигатуры матчить детерминированно, соединения разрешать только по метаданным и проверкам. Основной связный штрих может продолжиться к следующей букве, точки и перекладины откладываются в пределах разрешённой группы слова. Порядок не оптимизировать глобальным nearest-neighbour. При недопустимом соединении поднять перо, а не рисовать произвольную перемычку.

## ADR-07. Вариативность до измерения строки

Выбор формы, наклон и масштаб определяются до измерения реальной геометрии. Перенос не вызывает нового случайного выбора. После размещения разрешена только предусмотренная жёсткая трансформация строки в зарезервированном пространстве. Никакого независимого шума отдельных точек.

## ADR-08. Собственная простая вёрстка

Greedy word wrap по действительным границам чернил и advances. Словарные переносы по слогам отключены; длинное слово делится по графемам с повторным shaping фрагмента. Не вставлять смысловой дефис автоматически. NBSP не разрывать. Типографская оптимизация абзаца и двумерные формулы вне MVP.

## ADR-09. Устройство — явная граница

Page → Cartesian work plane → backend → transport. Первая виртуальная мишень декларирует XYZ и Z-перо исключительно для офлайн-проверок. Реальное оборудование получает новый профиль с подтверждёнными ограничениями. Не выводить кинематику, servo-команды и baudrate из названия платы.

## ADR-10. Контроллер выполняет динамику

Хост проверяет геометрию, порядок пера, ограничения подачи и бюджет аппроксимации. Реальное ускорение, look-ahead и генерация импульсов остаются контроллеру, если он заявляет соответствующую capability. Контроллер без motion planner потребует отдельного backend и испытаний, а не цикла sleep в Python.

## ADR-11. Разделить planned / accepted / executed

Подтверждение строки протоколом не доказывает физическое завершение. Коммуникация учитывает буфер, состояние устройства, таймауты и безопасные checkpoint. После потери связи не переотправлять движения автоматически. Возобновление возможно только с известного состояния и подтверждённой регистрации листа.

## ADR-12. Персонализация сначала по траекториям

II-A позволяет создавать персональный стиль без OCR и обучения. II-B сохраняет альтернативные гипотезы по изображениям. Распознанный текст и реконструированный порядок не считаются ground truth. CTC alignment помогает локализации, но не доказывает границы соединённых букв.

## ADR-13. Хранение и версии

I: UTF-8 JSON + неизменяемые файлы стиля и manifest; SQLite не нужен. II: SQLite для метаданных/исправлений, content-addressed файлы для изображений и траекторий. Публикация новой версии стиля атомарна; исправление исходника не меняет уже созданные задания. JSON schema major/minor и algorithm version разделены.

## ADR-14. Зависимости и лицензии

Предложение для будущего собственного кода — MIT; решение о публикации принадлежит правообладателю. Пакетам и данным сохраняются их лицензии. Код VHS AGPL и файлы без подтверждённой лицензии не копируются в ядро. Свободная доступность репозитория не равна разрешению на его включение в продукт. Ни один ML checkpoint не становится обязательным до проверки model card и лицензии данных.

## ADR-15. Preview и симуляция без UI-проекта

MVP выдаёт обычный SVG и диагностический SVG с номерами штрихов/поднятыми перемещениями, плюс машиночитаемый отчёт. Пользователь открывает SVG существующим просмотрщиком. Это удовлетворяет предпросмотру без разработки GUI. Будущий UI пользуется ApplicationService и CorrectionService, не получает доступ к порту или внутренним таблицам.

## ADR-16. Минимальный G-code backend

Собственный ограниченный emitter из валидированного MotionPlan оправдан тем, что нужно сохранять семантику и проверять каждый переход. Универсальный шаблонизатор vpype-gcode полезен для сравнения, но не становится authority команд пера. Строковые фрагменты G-code из текста, шрифта и произвольного профиля запрещены; новые команды добавляются версионированным диалектом.

## ADR-17. Ошибки не «исправляются» ценой текста

Нет обрезки буквы по полю, растяжения страницы под станок, замены Q на q, удаления точек как шума или пропуска проблемного слова. Валидация блокирует выпуск и возвращает точную позицию. Допустимые деградации — несоединённая пара и отключение вариативности с диагностикой, поскольку они сохраняют текст и явно описаны.

## ADR-18. Desktop GUI перенесён перед capture/OCR

По прямому решению пользователя 2026-10-13 desktop GUI выполняется после
программной вертикали этапа I и до Online Handwriting Capture. ADR-15 остаётся
исторически верным для первого CLI MVP, но больше не задаёт текущий порядок.

GUI — optional слой `handwriting_plotter.gui` на PySide6/Qt Widgets. Он вызывает
application API, не CLI subprocess и не внутренние таблицы shaping. Общий
PenPlan остаётся authority для canvas/export; диагностические scene items не
попадают в production artifacts. Project source хранится в versioned JSON,
generated artifacts можно воспроизвести. PySide6 не становится dependency
headless core.
