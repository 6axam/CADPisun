# Handwriting Plotter — инженерный проект

> **Установка без Git:** [пошаговая инструкция для Windows 10/11, Arch/Omarchy и Ubuntu](INSTALL.md) — скачивание ZIP, установка Python 3.12.12, PySide6 и запуск GUI.

Статус: программный MVP и desktop GUI этапа I реализованы и проверены
13 октября 2026 года. Аппаратный профиль и продуктовый украинский StylePack
остаются отдельными воротами; виртуальная симуляция не считается испытанием
реального станка.

## Назначение и исходные условия

Локальная программа получает текст, собирает его в рукописные страницы и преобразует упорядоченные движения пера в задания для пишущего станка. Основные языки — украинский, русский и английский. Первая целевая страница — A4. Разработка ориентирована на Python и Linux; наличие GPU не предполагается.

Предыдущий экспериментальный проект недоступен и не является зависимостью. Пользователь отвечает за программную часть, товарищ — за механику и электронику. Контроллер, кинематика, рабочее поле и механизм подъёма пера неизвестны. Документация не назначает им вымышленные характеристики. Синхронизированный каталог `sources/` остаётся справочным и неизменным.

## Архитектурный вердикт

Выбран подход C: собственное небольшое предметное ядро, готовые библиотеки на границах. Не форк монолитного генератора. Главный актив проекта — проверенная библиотека направленных рукописных штрихов и правила их соединения, а не OCR или генерация картинки.

Основной конвейер:

**Unicode → графемы → варианты букв и лигатуры → соединённые группы штрихов → страницы в миллиметрах → план пера → координаты оборудования → команды выбранного диалекта → транспорт.**

SVG и G-code строятся из общего плана. G-code никогда не получают обратным разбором собственного SVG. Фотография, контур чернил, центральная линия и записанная траектория хранятся как разные сущности.

Готовое покрытие качественной украинской скорописи у исследованных кандидатов не подтверждено. Поэтому производство стартового почерка — обязательная задача этапа I, с собственной приёмкой. Её нельзя подменить установкой Hershey Cyrillic. Обоснование и ссылки на код находятся в [RESEARCH.md](RESEARCH.md).

## Граница первого продукта

Первый законченный программный MVP включает:

- Один поставляемый стиль `ua-school-v1`, совместимый с UA/RU/EN, цифрами и явно перечисленной пунктуацией; три проверенных варианта строчных букв и минимум один вариант остальных обязательных знаков.
- CLI и библиотечный API, строгую проверку покрытия, размер, интервалы, поля, переносы и пагинацию.
- Связное письмо там, где набор данных разрешает соединение; отдельные штрихи и отложенные точки/надстрочные знаки.
- Воспроизводимость по тексту, версиям, параметрам и seed.
- Чистый SVG каждой страницы, диагностический SVG последовательности и JSON-отчёт симуляции.
- G-code для **явно искусственного** профиля `virtual-cartesian-z-v1`, его независимую проверку и симуляцию. Этот профиль описывает программную мишень, не реальный станок.

Аппаратный выпуск I-H добавляет один реальный профиль, диалект и отправку после определения оборудования. Он не блокирует программный MVP, но без него нельзя объявлять систему проверенной на станке. Нельзя обещать универсальный G-code, автоматическую смену листа или точность реального письма по одной симуляции.

«Произвольный текст» означает произвольную последовательность поддерживаемых графем без фиксированного набора фраз. Программа принимает Unicode, но не обязана рисовать любой символ Unicode. Emoji, неподдерживаемые системы письма, формулы с двумерной вёрсткой и неизвестные сочетания диакритик дают содержательную ошибку покрытия; буквы не исчезают и не заменяются молча.

## Этапы после MVP

II-A: импорт настоящих записей пера, ручная разметка и версии персонального стиля. Это наиболее надёжный путь персонализации и может предшествовать OCR.

II-B: фотографии/сканы, коррекция геометрии, распознавание строк, гипотезы сегментации, восстановление центральных линий, обязательная проверка человеком. Клонирование неизвестного порядка штрихов не обещается.

II-C: обучение HTR на исправлениях и исследовательский адаптер восстановления траекторий. ML работает в отдельных локальных окружениях.

III: дополнительные стили, устройства, более сложные лигатуры и генеративные
модели. По прямому решению пользователя desktop GUI перенесён в этап I и уже
реализован поверх того же application API, что использует CLI.

## Desktop GUI

Установка и запуск на Linux/Omarchy:

```sh
uv sync --python 3.12.12 --extra gui
uv run hplot-gui
```

Приложение создаёт текстовые объекты на A4, позволяет выбрать установленную
ревизию StylePack, настроить координаты и размер письма, выделять и перемещать
объекты мышью. Интерфейс переключается между английским и украинским. Объект
сетки настраивает размер клеток, цвет, вид линий и частичную привязку по X/Y;
это только вспомогательный слой холста, который не входит в SVG, PenPlan или
G-code. Проект сохраняется в переносимый `*.hplot.json`.
Production SVG, diagnostic SVG, validation JSON и virtual G-code экспортируются
по отдельности. Отправки на реальный станок нет.

Подробный сценарий, сочетания клавиш и ограничения описаны в
[руководстве по GUI](docs/gui-usage.md). Снимок рабочего интерфейса находится в
[`examples/gui/handwriting-plotter-gui.png`](examples/gui/handwriting-plotter-gui.png).

## Готовность к передаче

Спецификация передана в реализацию. Программные I-00…I-08 и техническая часть I-09 выполнены; продуктовый выпуск остаётся на воротах авторского `ua-school-v1`. Знание станка для этой работы не требовалось. Испытание конкретного аппаратного профиля по-прежнему относится только к I-H.

Открытые вопросы сгруппированы по моменту, когда ответы действительно нужны, в [RISKS.md](RISKS.md). Сейчас нет вопроса, требующего остановить подготовку программной архитектуры.

## Текущее состояние реализации

Программная вертикаль этапа I реализована до атомарного bundle:
Unicode → StylePack → shaping → A4 layout → PenPlan → SVG → virtual MotionPlan
→ независимо проверяемый G-code. Команды запуска и состав результата описаны в
[docs/usage.md](docs/usage.md), история ворот — в
[docs/implementation-status.md](docs/implementation-status.md).

Для технической проверки включён `test-technical-v1`: читаемый одноштриховой
small-caps fixture с полным обязательным набором UA/RU/EN, цифр и знаков. Он
явно не является рукописным продуктовым стилем. Выпуск `ua-school-v1` остаётся
заблокирован авторскими образцами и визуальной приёмкой; точные условия записаны
в [docs/blockers.md](docs/blockers.md).

Для предметной проверки связной скорописи добавлен отдельный
`ua-school-v1-pilot` revision `0.1.0`: 26 символов, 32 направленных варианта,
baseline anchors, отложенные украинские диакритики и frozen corpus из семи
слов. Он по-прежнему `test_only=true` и `production_eligible=false`.
[SVG и PNG для визуальной оценки](examples/ua-school-pilot/README.md) не
являются человеческой приёмкой продуктового `ua-school-v1`.
